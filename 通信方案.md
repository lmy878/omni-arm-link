# IEEE 802.11-Based Wireless Communication Plan for Competition Robots

## 1. Project Objective

The goal is to build a reliable, low-latency and bidirectional wireless communication link for a competition robot.

### Hardware Platforms

- Controller: Raspberry Pi 4B
- Robot: NVIDIA Jetson Orin
- Third node: passive Monitor for packet logging and link analysis
- No additional MCU is used as the main communication controller

### Data Requirement

The robot transmits at 200 Hz:

- 5 quaternions: 5 × 4 × `float32`
- 15 single-point laser measurements: 15 × `float32`
- 50 robot state values: 50 × `float32`

Per frame:

\[
(5\times4+15+50)\times4=340\text{ Bytes}
\]

At 200 Hz:

\[
340\times200\times8=544\text{ kbps}
\]

Therefore:

- Robot → Controller: approximately **544 kbps raw payload**
- Controller → Robot: much lower bandwidth, mainly joystick, buttons, modes, emergency stop and control parameters
- The system is a strongly **asymmetric bidirectional link**

---

## 2. Why Raw IEEE 802.11

The competition rules permit IEEE 802.11-based communication.

Instead of relying on a conventional Wi-Fi network, the project focuses on:

- Low latency
- Low jitter
- High robustness
- FEC
- Broadcast capability
- Multiple receivers
- Link-quality monitoring
- Passive packet monitoring

The preferred approach therefore uses:

- Monitor Mode
- Raw Frame Injection
- Broadcast
- FEC
- Custom data streams

This uses IEEE 802.11 radio hardware without requiring a conventional AP/STA network.

---

# 3. OpenHD Approach

## 3.1 Overview

OpenHD is an open-source digital radio system designed primarily for unmanned systems.

Typical functions include:

- FPV video
- Telemetry
- MAVLink
- RC
- OSD
- Link monitoring

Its radio layer can use IEEE 802.11 adapters with Monitor Mode and Packet Injection to establish a low-latency link.

```text
Raspberry Pi 4B
      │
   OpenHD
      │
802.11 Radio
      )))
      ))) Raw IEEE 802.11
      (((
      (((
802.11 Radio
      │
   OpenHD
      │
 Jetson Orin
```

## 3.2 Advantages

- Mature open-source project
- Designed for unmanned-system communication
- Integrated FEC, telemetry, RC and link monitoring
- Good reference implementation for Raw IEEE 802.11
- Mature Wi-Fi adapter and driver ecosystem

## 3.3 Suitability for This Project

The project does not require video transmission.

Required data mainly consists of:

- Quaternions
- Laser measurements
- Robot states
- Control commands
- Debug information

OpenHD includes many unnecessary components:

- Video pipeline
- Camera support
- Encoder
- OSD
- Extensive MAVLink / FPV functions

Therefore:

> **OpenHD is more suitable as a technical reference than as the complete final software stack.**

## 6.1 Controller → Robot

Contains:

- Joystick commands
- Buttons
- Operating mode
- Emergency stop
- Control parameters

Characteristics:

- Low bandwidth
- Highest real-time priority
- Strong FEC and redundancy are recommended

```text

High Priority
Strong FEC
Redundant Critical Commands
```

## 6.2 Robot → Controller

Contains:

- 5 quaternions
- 15 single-point laser measurements
- 50 robot state values

Raw traffic:

```text
340 Bytes/frame
200 Hz
≈ 544 kbps
```

A practical link budget of approximately:

```text
~1 Mbps
```

should be reserved for:

- Headers
- FEC
- Sequence numbers
- Timestamps
- Redundancy
- Additional robot states

# 8. Passive Monitor Node

The Monitor uses another IEEE 802.11 adapter supporting Monitor Mode.

```text
               Controller
                   ▲
                   │
              Raw 802.11
                   │
                   ▼
                 Robot

                   │
                   │ Passive RX
                   ▼

                Monitor
```

The Monitor:

- Does not transmit control commands
- Does not participate in the primary link
- Must not become a dependency of Controller ↔ Robot communication

Functions:

- Record Controller → Robot packets
- Record Robot → Controller packets
- Monitor packet loss
- Monitor link quality
- Save competition logs
- Analyze robot states in real time

Failure of the Monitor must have no effect on the main communication link.

# 基于 IEEE 802.11 的机器人无线通信方案

## 1. 项目目标

面向比赛机器人，设计一套高可靠、低延迟、双向无线通信链路。

### 硬件平台

- 遥控器端：Raspberry Pi 4B
- 机器人端：NVIDIA Jetson Orin
- 第三节点：Monitor，用于被动监听、记录和分析通信数据
- 不额外引入 MCU 作为通信主控

### 数据需求

机器人端以 200 Hz 发送：

- 5 组四元数：5 × 4 × `float32`
- 15 个单点激光数据：15 × `float32`
- 50 个机器人状态量：50 × `float32`

每帧数据量：

\[
(5\times4+15+50)\times4=340\text{ Bytes}
\]

200 Hz 下：

\[
340\times200\times8=544\text{ kbps}
\]

因此：

- Robot → Controller：约 **544 kbps 原始 Payload**
- Controller → Robot：主要为摇杆、按键、模式、急停和少量控制参数，带宽显著更低
- 整体属于**非对称双向通信**

---

## 2. 为什么采用 IEEE 802.11 Raw Link

比赛规则允许 IEEE 802.11 类无线通信。

本项目不追求传统 Wi-Fi 网络功能，而更关注：

- 低延迟
- 低延迟抖动
- 强抗干扰能力
- FEC 冗余
- 广播能力
- 多接收节点
- 链路质量监测
- 第三节点被动监听

因此重点考虑基于 IEEE 802.11 无线芯片的：

- Monitor Mode
- Raw Frame Injection
- Broadcast
- FEC
- 自定义数据流

即采用“IEEE 802.11 无线 PHY/MAC 能力”，但不依赖传统 AP/STA 网络模式。

---

# 3. OpenHD 方案

## 3.1 简介

OpenHD 是面向无人系统的开源数字无线通信平台，主要用于：

- FPV 视频
- Telemetry
- MAVLink
- RC
- OSD
- 链路监控

其底层可以利用支持 Monitor Mode 和 Packet Injection 的 IEEE 802.11 无线网卡建立低延迟无线链路。

典型结构：

```text
Raspberry Pi 4B
      │
   OpenHD
      │
802.11 Radio
      )))
      )))  Raw IEEE 802.11
      (((
      (((
802.11 Radio
      │
   OpenHD
      │
 Jetson Orin
```

## 3.2 优点

- 项目成熟度较高
- 已针对无人系统通信进行大量工程优化
- 已集成 FEC、遥测、RC、链路状态监控等功能
- 可作为 IEEE 802.11 Raw Link 的重要实现参考
- 有较成熟的无线网卡和驱动生态

## 3.3 与本项目的匹配度

本项目没有图传需求，主要传输：

- 四元数
- 激光测距
- 机器人状态
- 控制命令
- 调试信息

而 OpenHD 包含大量本项目不需要的功能：

- Video Pipeline
- Camera
- Encoder
- OSD
- 大量 MAVLink / FPV 功能

因此：

> **OpenHD 更适合作为技术参考，而不是直接作为最终完整软件栈。**

# 8. 第三节点 Monitor

Monitor 使用另一块支持 Monitor Mode 的 IEEE 802.11 网卡。

结构：

```text
               Controller
                   ▲
                   │
                   │
              Raw 802.11
                   │
                   ▼
                 Robot

                   │
                   │ Passive RX
                   ▼

                Monitor
```

Monitor：

- 不发送控制数据
- 不发送 ACK
- 不参与主链路调度
- 不成为 Controller 与 Robot 通信的依赖

主要功能：

- 记录 Controller → Robot 数据
- 记录 Robot → Controller 数据
- 查看丢包率
- 查看链路状态
- 保存比赛日志
- 实时分析机器人状态

即使 Monitor：

- 关机
- 崩溃
- 掉线

Controller ↔ Robot 主链路仍正常工作。
